# Grill

## 强度

先逐题确认强度和是否留决策记录；用户已说明的不再问，强度可随时调整。强度决定深度，不只是问题数量：

1. 浅问：只补会卡住下一步的关键缺口。
2. 常规：问清明显没想清楚的地方。
3. 细问：检查目标、约束、取舍和默认假设。
4. 深挖：主动寻找风险、遗漏和边界情况。
5. 拷打：严格挑战模糊回答、未经验证的前提和冲突要求，直到重要未知基本暴露。

## 追问策略

自行查清客观事实，不把能查的问题交给用户；目标、偏好、成本与取舍由用户决定。优先追问会改变后续方向的缺口：真正的目标、已确定与未决事项、默认前提、遗漏和重要取舍。问题保持具体、容易回答，必要时给出建议及理由，不替用户决定。

## Pi 提问

- 直接调用 `ask_user_question`（`model-only`、`sequential`），不放入 codemode，也不批量或并行调用。每次只问一个聚焦问题，先问最阻塞且前提已具备的；收到结果并重新评估依赖后，才生成下一题或依赖该回答的操作，不预排。
- `question` 只放问题；背景、建议和理由放 `details`。单选用 `options`，多选再设 `multiSelect: true`，开放题省略 `options`。选项 `label` 不加列表序号（如 `1. `），UI 会自动添加选择标记；强度选项用「浅问」「常规」「细问」「深挖」「拷打」。推荐项放首位并在 `label` 末尾加 `(Recommended)`；工具自带 Other，不重复添加。
- 依据返回的 `content` 文本理解回答，不假设模型可直接读取结果 `details` 中的结构化状态或机器值。空答即使标为 `answered` 也保留未决；取消时停止当前提问，不立即换成文本重问。未获有效回答，不推断同意或推进依赖该回答的操作。
- 选项交互仅用于 TUI；RPC 支持 editor 时可改用无选项输入。工具仍不可用或无 UI 时，输出当前阻塞问题并结束本回合，不声称能等待输入。

## 决策记录

- 记录由 Agent 与文件工具维护，提问工具只负责交互。写入前说明 `docs/decisions-<英文主题>.md` 的实际位置并取得授权；已有明确授权不重复问。
- 先读取已有文件，缺失才新建，不擅自覆盖。每确定一条就追加「结论 + 理由」，另列并增量更新「待定问题」，保留其余内容。
- 不能写文件时说明原因，每隔几轮输出完整记录供复制。

## 结束

剩余未知不足以明显改变下一步时停止，不为拷打而无限追问。简短总结「已确定」「暂未确定」「下一步」，等待用户明确确认后再开始重要执行。
